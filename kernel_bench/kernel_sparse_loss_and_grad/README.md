# kernel_sparse_loss_and_grad Replacement

## Overview

This benchmark suite replaces the `kernel_sparse_loss_and_grad` CUDA kernel with a library-based implementation using **thrust**, **CUB**, and **cuBLAS**.

### Original Kernel
- **Location**: `gpu_autoencoder.cu:59-79` (kernel definition), line 334 (launcher)
- **What it does**: 
  - Iterates through sparse CSC-format target matrix (d0 × B, nnz entries)
  - For each sparse entry (r, j, v):
    - Updates gradient: `d_grad_loss[r,j] = (A_L[r,j] - v) / B`
    - Accumulates loss: `loss_acc += v^2 - 2*A_L[r,j]*v` (atomic)
  - Note: Caller pre-fills `d_grad_loss = A_L / B` before calling this kernel

## Replacement Strategy

The replacement uses CUDA libraries to implement the same computation:

### Gradient Update (thrust + custom kernel)
- Since we need gather-compute-scatter semantics (load A_L at sparse positions, compute, scatter back), and thrust doesn't provide a direct "gather-compute-scatter" primitive, we use a small custom kernel.
- The custom kernel iterates over the nnz entries, finds the column index j via linear search through col_ptr, loads A_L[r,j], computes (A_L[r,j] - v) / B, and writes back to d_grad_loss[r,j].

### Loss Computation (CUB DeviceReduce::Sum)
- Create a transform iterator that maps each entry index k to the loss term: `v^2 - 2*A_L[r,j]*v`
- Use `cub::DeviceReduce::Sum` to reduce the transformed sequence
- Result is a single scalar sum

## Files

- `original.cu` — Original kernel + launcher (verbatim from gpu_autoencoder.cu)
- `replacement.cu` — Library-based replacement (thrust custom kernel + CUB reduce)
- `reference.py` — Python reference that generates test data and expected outputs
- `test_accuracy.cu` — Loads .bin files, runs both kernels, compares outputs
- `bench.cu` — Benchmarks both kernels (10 warmup + 100 timed iterations)
- `Makefile` — Builds `test_accuracy` and `bench` targets
- `run_tests.sh` — SLURM script to run full pipeline

## Compilation

All `.cu` files use C++17 and target `sm_90` (H100). To compile on login node (compile-only check):

```bash
# Compile individual object files
/usr/local/cuda/bin/nvcc -c -O3 -std=c++17 --gpu-architecture=sm_90 \
  -I/usr/local/cuda/include original.cu -o /tmp/orig_klg.o

/usr/local/cuda/bin/nvcc -c -O3 -std=c++17 --gpu-architecture=sm_90 \
  -I/usr/local/cuda/include replacement.cu -o /tmp/repl_klg.o

# Link test_accuracy
/usr/local/cuda/bin/nvcc -O3 -std=c++17 --gpu-architecture=sm_90 \
  -I/usr/local/cuda/include test_accuracy.cu original.cu replacement.cu \
  -o /tmp/link_klg_test -L/usr/local/cuda/lib64 \
  -lcudart -lcublas -lcusparse -lnvToolsExt -lpthread

# Link bench
/usr/local/cuda/bin/nvcc -O3 -std=c++17 --gpu-architecture=sm_90 \
  -I/usr/local/cuda/include bench.cu original.cu replacement.cu \
  -o /tmp/link_klg_bench -L/usr/local/cuda/lib64 \
  -lcudart -lcublas -lcusparse -lnvToolsExt -lpthread
```

Generated by `reference.py`:
- **d0 = 64**, **B = 32**, **~5% sparsity** (~100 non-zeros)
- **Inputs**: `a_L.bin`, `col_ptr.bin`, `row_idx.bin`, `values.bin` (CSC sparse targets)

- **Metadata**: `meta.txt` (d0, B, nnz)

## Accuracy Tolerance

- **Gradient**: relative error ≤ 1e-5, absolute error ≤ 1e-6
- **Loss**: same

## Concerns / Notes

1. **Column index lookup in custom kernel**: Uses linear search over col_ptr. For larger B, could optimize with binary search.
2. **CUB memory allocation**: Allocates temporary storage inside the replacement launch function; may have cleanup overhead.
3. **AtomicAdd in original**: The original uses atomic operations on loss_acc; CUB DeviceReduce is more efficient and does not require atomics.
4. **No cuDNN**: Per requirements, replacement does not use cuDNN.
