# ReLU Backward Kernel Replacement Benchmark

## Overview

This directory contains a benchmark suite for comparing the original `kernel_relu_backward` implementation with a Thrust-based replacement.

**Target Kernel**: `kernel_relu_backward` from `/mnt/home/besleya/autoencoder/layer.cu`

**Algorithm**: ReLU backward gating
```
dz[i] *= (z[i] > 0.0f) ? 1.0f : 0.0f
```

## Strategy

**Original Implementation**: Hand-written CUDA kernel with explicit thread indexing.

**Replacement**: Thrust-based using `thrust::transform` with device lambda:
```cpp
thrust::transform(
    thrust::cuda::par.on(stream),
    dz, dz + size,           // gradient input
    z,                        // activation input
    dz,                       // output (in-place)
    [] __device__ (float g, float zv) {
        return zv > 0.0f ? g : 0.0f;
    }
);
```

## Files

- **original.cu**: Verbatim kernel definition and launcher wrapper from layer.cu
- **replacement.cu**: Thrust-based implementation
- **reference.py**: PyTorch CPU reference for generating test data
- **test_accuracy.cu**: Accuracy validation (rel_tol=1e-5, abs_tol=1e-6)
- **bench.cu**: Performance benchmark (10 warmup + 100 timed iterations)
- **Makefile**: Build rules for test_accuracy and bench
- **run_tests.sh**: SLURM job script orchestrating full workflow

## Test Data

Generated by `reference.py`:
- **Size**: 131,072 elements
- **dz_init**: Random floats in [-1, 1]
- **z**: Random floats in [-1, 1]
- **expected_dz**: `where(z > 0, dz_init, 0)` (PyTorch CPU)

Output files:
- `dz_init.bin`: Initial gradient buffer
- `z.bin`: Activation values
- `expected_dz.bin`: Ground truth output
- `meta.txt`: Metadata (size, seed)

## Accuracy Testing

`test_accuracy` loads reference data, runs both implementations, and compares:
- **Relative tolerance**: 1e-5
- **Absolute tolerance**: 1e-6
- **Pass criterion**: All elements satisfy `abs_err <= abs_tol OR rel_err <= rel_tol`

## Performance Benchmark

`bench` measures per-iteration execution time:
- **Warmup**: 10 iterations (GPU cache warming)
- **Timed**: 100 iterations with CUDA events
- **Per-iteration**: dz reset from dz_init, kernel execution measured
- **Output**: Median time (ms), average time (ms), speedup factor

## Compilation Flags

- **Optimization**: `-O3`
- **C++ Standard**: `-std=c++17`
- **GPU Architecture**: `--gpu-architecture=sm_90`
- **Extended Lambda**: `--extended-lambda` (required for device lambdas)
- **Libraries**: `-lcudart -lcublas -lcusparse -lnvToolsExt -lpthread`

## Expected Behavior

### Accuracy
Both implementations should pass with zero errors.

### Performance
- **Original**: Baseline performance (hand-written kernel)
- **Thrust**: May be comparable or faster depending on Thrust optimization for this operation

## Concerns & Notes

- **No cuDNN**: Per specification, thrust-only replacement (no cuDNN dependencies)
- **Stream Support**: Both implementations accept cudaStream_t for async execution
- **In-Place Operation**: dz is modified in-place (no separate output buffer)
- **Synchronization**: Benchmarks explicitly synchronize after each kernel to ensure fair timing
